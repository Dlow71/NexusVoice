## 1. 策略模式概述

### 1.1 什么是策略模式

策略模式（Strategy Pattern）是一种**行为设计模式**，它定义一系列算法，将每个算法封装起来，使它们可以相互替换。策略模式让算法独立于使用它的客户端而变化。

### 1.2 为什么使用策略模式

在文档处理场景中：

#### ❌ 不使用策略模式的问题

```java
// 糟糕的设计：if-else地狱
public class DocumentProcessor {
    public void processDocument(String fileId, String fileType) {
        if ("PDF".equals(fileType)) {
            // PDF处理逻辑（100行代码）
            downloadPdf();
            convertPdfToImage();
            callOCRAPI();
            saveToDatabase();
        } else if ("DOCX".equals(fileType)) {
            // Word处理逻辑（100行代码）
            downloadWord();
            parseWithPOI();
            extractText();
            saveToDatabase();
        } else if ("TXT".equals(fileType)) {
            // TXT处理逻辑（50行代码）
            downloadTxt();
            readText();
            splitText();
            saveToDatabase();
        } else if ("MARKDOWN".equals(fileType)) {
            // Markdown处理逻辑（150行代码）
            downloadMarkdown();
            parseStructure();
            extractSegments();
            saveToDatabase();
        }
        // 每增加一种格式，这个类就变得更臃肿
    }
}
```

**问题**:
1. ⚠️ 违反单一职责原则：一个类处理所有格式
2. ⚠️ 违反开闭原则：每次新增格式都要修改此类
3. ⚠️ 代码臃肿：一个类上千行代码
4. ⚠️ 难以测试：逻辑耦合严重
5. ⚠️ 难以维护：修改一个格式可能影响其他格式

#### ✅ 使用策略模式的优势

```java
// 优秀的设计：策略模式
public interface DocumentProcessingStrategy {
    void handle(RagDocMessage message, String strategy) throws Exception;
}

// PDF策略
@Service("pdf")
public class PDFStrategy implements DocumentProcessingStrategy {
    // 只负责PDF处理（100行代码）
}

// Word策略
@Service("word")
public class WordStrategy implements DocumentProcessingStrategy {
    // 只负责Word处理（100行代码）
}

// 使用工厂模式选择策略
DocumentProcessingStrategy strategy = factory.getStrategy(fileType);
strategy.handle(message, fileType);
```

**优势**:
1. ✅ 符合单一职责原则：每个策略类只处理一种格式
2. ✅ 符合开闭原则：新增格式只需新增策略类
3. ✅ 代码清晰：每个类职责明确
4. ✅ 易于测试：可独立测试每个策略
5. ✅ 易于维护：修改互不影响

## 3. 核心代码实现

### 3.1 策略接口

```java
package org.xhy.domain.rag.strategy;

import org.xhy.domain.rag.message.RagDocMessage;

/**
 * 文档处理策略接口
 * 
 * 定义所有文档处理器必须实现的方法
 * 
 * @author AgentX Team
 * @date 2024
 */
public interface DocumentProcessingStrategy {
    
    /**
     * 处理文档的核心方法
     * 
     * @param ragDocMessage MQ消息对象，包含文件ID、用户ID、模型配置等信息
     * @param strategy 策略类型（PDF/WORD/TXT/MARKDOWN）
     * @throws Exception 处理过程中的异常
     */
    void handle(RagDocMessage ragDocMessage, String strategy) throws Exception;
}
```

### 3.2 抽象策略类

```java
package org.xhy.domain.rag.strategy.impl;

import java.util.Map;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.xhy.domain.rag.message.RagDocMessage;
import org.xhy.domain.rag.strategy.DocumentProcessingStrategy;

/**
 * 抽象文档处理策略
 * 
 * 实现了通用的文档处理流程（模板方法模式）
 * 子类只需实现具体的解析逻辑
 * 
 * @author AgentX Team
 */
public abstract class AbstractDocumentProcessingStrategy 
        implements DocumentProcessingStrategy {
    
    private static final Logger LOG = LoggerFactory.getLogger(
        AbstractDocumentProcessingStrategy.class
    );
    
    /**
     * 模板方法：定义文档处理的标准流程
     * 
     * 流程：
     * 1. 获取文件数据（从存储服务下载）
     * 2. 计算页数/段落数（更新数据库）
     * 3. 处理文件内容（OCR/解析）
     * 4. 保存到数据库（document_unit表）
     * 
     * @param ragDocMessage MQ消息
     * @param strategy 策略类型
     */
    @Override
    public void handle(RagDocMessage ragDocMessage, String strategy) 
            throws Exception {
        
        // Step 1: 下载文件数据
        final byte[] fileData = getFileData(ragDocMessage, strategy);
        if (fileData == null) {
            LOG.error("文件数据为空，fileId: {}", ragDocMessage.getFileId());
            return;
        }
        LOG.info("成功下载文件数据，大小: {} bytes", fileData.length);
        
        // Step 2: 计算文件页数/段落数
        pushPageSize(fileData, ragDocMessage);
        Integer pageSize = ragDocMessage.getPageSize();
        if (pageSize == null) {
            LOG.warn("页面大小为空，使用默认值1（适用于txt/word文件）");
            pageSize = 1;
        }
        LOG.info("文件总页数/段落数: {}", pageSize);
        
        // Step 3: 处理文件内容（OCR/解析）
        final Map<Integer, String> data = processFile(
            fileData, pageSize, ragDocMessage
        );
        LOG.info("成功从当前文件获取 {} 页数据", data.size());
        
        // Step 4: 保存数据到数据库
        insertData(ragDocMessage, data);
        LOG.info("文件处理完成，fileId: {}", ragDocMessage.getFileId());
    }
    
    // ==================== 抽象方法（子类必须实现） ====================
    
    /**
     * 获取文件页数/段落数
     * 
     * 不同格式的文档计算方式不同：
     * - PDF: 使用PDFBox获取页数
     * - Word/TXT: 使用LangChain4j分割器计算段落数
     * - Markdown: 使用结构化解析器计算段落数
     * 
     * @param bytes 文件字节数组
     * @param ragDocSyncOcrMessage MQ消息（用于设置pageSize）
     */
    abstract public void pushPageSize(
        byte[] bytes, 
        RagDocMessage ragDocSyncOcrMessage
    );
    
    /**
     * 获取文件数据
     * 
     * 从文件存储服务（S3/OSS/MinIO）下载文件
     * 
     * @param ragDocSyncOcrMessage MQ消息
     * @param strategy 策略类型
     * @return 文件字节数组
     */
    abstract public byte[] getFileData(
        RagDocMessage ragDocSyncOcrMessage, 
        String strategy
    );
    
    /**
     * 处理文件内容
     * 
     * 返回格式：Map<页码/段落索引, 文本内容>
     * 
     * @param fileBytes 文件字节数组
     * @param totalPages 总页数/段落数
     * @return 处理结果
     */
    abstract public Map<Integer, String> processFile(
        byte[] fileBytes, 
        int totalPages
    );
    
    /**
     * 处理文件内容（带消息参数，子类可选择性重写）
     * 
     * 某些策略需要用到消息中的配置信息（如PDF的OCR模型配置）
     * 
     * @param fileBytes 文件字节数组
     * @param totalPages 总页数/段落数
     * @param ragDocSyncOcrMessage MQ消息
     * @return 处理结果
     */
    public Map<Integer, String> processFile(
        byte[] fileBytes, 
        int totalPages, 
        RagDocMessage ragDocSyncOcrMessage
    ) {
        // 默认调用不带消息参数的方法
        return processFile(fileBytes, totalPages);
    }
    
    /**
     * 保存数据到数据库
     * 
     * 将处理后的文本内容保存到document_unit表
     * 
     * @param ragDocSyncOcrMessage MQ消息
     * @param ocrData 处理结果 Map<页码, 文本内容>
     * @throws Exception 保存异常
     */
    abstract public void insertData(
        RagDocMessage ragDocSyncOcrMessage, 
        Map<Integer, String> ocrData
    ) throws Exception;
}
```

### 3.3 策略枚举

```java
package org.xhy.domain.rag.model.enums;

import java.util.Set;

/**
 * 文档处理类型枚举
 * 
 * 将文件扩展名映射到Spring Bean名称
 * 实现文件类型到处理策略的自动匹配
 * 
 * @author AgentX Team
 */
public enum DocumentProcessingType {
    
    /**
     * PDF策略
     * 支持格式：PDF
     * Bean名称：pdf
     * 处理方式：GPT-4V OCR识别
     */
    PDF(Set.of("PDF"), "pdf"),
    
    /**
     * Word/Office策略
     * 支持格式：DOC, DOCX, PPT, PPTX, XLS, XLSX
     * Bean名称：word
     * 处理方式：Apache POI解析
     */
    DOCX(Set.of("DOC", "DOCX", "PPT", "PPTX", "XLS", "XLSX"), "word"),
    
    /**
     * 纯文本策略
     * 支持格式：TXT, HTML
     * Bean名称：txt
     * 处理方式：直接读取文本
     */
    TXT(Set.of("TXT", "HTML"), "txt"),
    
    /**
     * Markdown策略
     * 支持格式：MD, MARKDOWN
     * Bean名称：markdown
     * 处理方式：结构化解析
     */
    MARKDOWN(Set.of("MD", "MARKDOWN"), "markdown");
    
    /**
     * 支持的文件扩展名集合
     */
    private final Set<String> value;
    
    /**
     * Spring Bean名称
     */
    private final String label;
    
    DocumentProcessingType(Set<String> value, String label) {
        this.value = value;
        this.label = label;
    }
    
    /**
     * 根据文件扩展名获取Bean名称
     * 
     * 使用示例：
     * DocumentProcessingType.getLabelByValue("PDF")  // 返回 "pdf"
     * DocumentProcessingType.getLabelByValue("DOCX") // 返回 "word"
     * 
     * @param label 文件扩展名（大写，如"PDF"）
     * @return Spring Bean名称（小写，如"pdf"）；不支持的格式返回null
     */
    public static String getLabelByValue(String label) {
        for (DocumentProcessingType enumValue : DocumentProcessingType.values()) {
            if (enumValue.value.contains(label)) {
                return enumValue.label;
            }
        }
        return null;
    }
    
    public Set<String> getValue() {
        return value;
    }
    
    public String getLabel() {
        return label;
    }
}
```

### 3.4 策略工厂

```java
package org.xhy.domain.rag.strategy.context;

import java.util.Map;
import org.springframework.stereotype.Service;
import org.xhy.domain.rag.model.enums.DocumentProcessingType;
import org.xhy.domain.rag.strategy.DocumentProcessingStrategy;
import jakarta.annotation.Resource;

/**
 * 文档处理策略工厂
 * 
 * 根据文件扩展名自动选择对应的处理策略
 * 使用Spring的依赖注入自动收集所有策略实例
 * 
 * @author AgentX Team
 */
@Service
public class DocumentProcessingFactory {
    
    /**
     * Spring自动注入所有DocumentProcessingStrategy的实现类
     * 
     * Map的Key：Spring Bean名称（pdf/word/txt/markdown）
     * Map的Value：对应的处理策略实例
     * 
     * Spring会自动收集所有带@Service注解且实现了DocumentProcessingStrategy接口的类
     * 例如：
     * - @Service("pdf") -> PDFRagDocDocumentProcessing实例
     * - @Service("word") -> WORDDocumentProcessing实例
     * - @Service("txt") -> TXTRagDocDocumentProcessing实例
     * - @Service("markdown") -> MarkdownRagDocumentProcessing实例
     */
    @Resource
    private Map<String, DocumentProcessingStrategy> documentProcessingStrategyMap;
    
    /**
     * 根据文件扩展名获取对应的文档处理策略
     * 
     * 查找流程：
     * 1. 文件扩展名（如"PDF"） 
     *    ↓
     * 2. DocumentProcessingType枚举转换
     *    ↓
     * 3. Bean名称（如"pdf"）
     *    ↓
     * 4. 从Map中获取对应的策略实例
     * 
     * @param strategy 文件扩展名（大写，如"PDF"/"DOCX"/"TXT"/"MD"）
     * @return 对应的处理策略实例；不支持的格式返回null
     */
    public DocumentProcessingStrategy getDocumentStrategyHandler(String strategy) {
        // 通过枚举类将扩展名转换为Bean名称
        String beanName = DocumentProcessingType.getLabelByValue(strategy);
        
        if (beanName == null) {
            return null;
        }
        
        // 从Spring容器中获取对应的策略实例
        return documentProcessingStrategyMap.get(beanName);
    }
    
    /**
     * 获取所有已注册的策略
     * 
     * @return 所有策略实例的Map
     */
    public Map<String, DocumentProcessingStrategy> getAllStrategies() {
        return documentProcessingStrategyMap;
    }
}
```

## 4. Spring Bean自动注入机制

### 4.1 注入原理

Spring会自动收集所有实现了`DocumentProcessingStrategy`接口的Bean，并注入到Map中：

```java
// Spring扫描到的Bean:
@Service("pdf")    → PDFRagDocDocumentProcessing实例
@Service("word")   → WORDDocumentProcessing实例
@Service("txt")    → TXTRagDocDocumentProcessing实例
@Service("markdown") → MarkdownRagDocumentProcessing实例

// 自动注入到Map:
Map<String, DocumentProcessingStrategy> strategyMap = {
    "pdf" -> PDFRagDocDocumentProcessing实例,
    "word" -> WORDDocumentProcessing实例,
    "txt" -> TXTRagDocDocumentProcessing实例,
    "markdown" -> MarkdownRagDocumentProcessing实例
}
```

### 4.2 Bean命名规则

```java
// 方式1：使用@Service注解指定Bean名称
@Service("pdf")  // Bean名称为"pdf"
public class PDFRagDocDocumentProcessing extends AbstractDocumentProcessingStrategy {
}

// 方式2：不指定名称，默认为类名首字母小写
@Service  // Bean名称为"pdfRagDocDocumentProcessing"
public class PDFRagDocDocumentProcessing extends AbstractDocumentProcessingStrategy {
}

// 推荐使用方式1，Bean名称简洁明了
```

### 4.3 注入验证

可以在启动时验证所有策略是否正确注入：

```java
@Component
public class StrategyValidator implements ApplicationRunner {
    
    @Resource
    private DocumentProcessingFactory factory;
    
    @Override
    public void run(ApplicationArguments args) {
        log.info("验证文档处理策略注入情况:");
        factory.getAllStrategies().forEach((name, strategy) -> {
            log.info("  - {}: {}", name, strategy.getClass().getSimpleName());
        });
    }
}

// 控制台输出：
// 验证文档处理策略注入情况:
//   - pdf: PDFRagDocDocumentProcessing
//   - word: WORDDocumentProcessing
//   - txt: TXTRagDocDocumentProcessing
//   - markdown: MarkdownRagDocumentProcessing
```

## 5. 策略模式优势总结

### 5.1 SOLID原则体现

| 原则 | 说明 | 体现 |
|-----|------|------|
| **S**ingle Responsibility | 单一职责 | 每个策略类只负责一种格式 |
| **O**pen/Closed | 开闭原则 | 新增格式无需修改现有代码 |
| **L**iskov Substitution | 里氏替换 | 所有策略可互相替换 |
| **I**nterface Segregation | 接口隔离 | 接口方法精简，不强制实现无关方法 |
| **D**ependency Inversion | 依赖倒置 | 依赖抽象接口，不依赖具体实现 |

### 5.2 设计模式组合

- ✅ **策略模式（Strategy Pattern）**: 定义算法族
- ✅ **工厂模式（Factory Pattern）**: 创建策略实例
- ✅ **模板方法模式（Template Method）**: 定义处理流程
- ✅ **依赖注入（Dependency Injection）**: Spring自动装配

### 5.3 扩展性示例

**新增CSV格式支持**，只需3步：

```java
// Step 1: 添加枚举值

// Step 3: 无需修改其他代码！Spring会自动注入
```
