## 1. 系统概述

### 1.1 业务背景

AgentX RAG系统需要支持多种格式的文档处理，包括PDF、Word、TXT、Markdown等。为了实现**高扩展性**和**低耦合**，系统采用了**策略模式（Strategy Pattern）**来处理不同格式的文档。

### 1.2 核心特性

- ✅ **多格式支持**: PDF、DOCX、PPT、XLS、TXT、HTML、Markdown
- ✅ **异步处理**: 基于RabbitMQ的消息队列异步处理
- ✅ **智能切片**: 根据文档类型自动选择切片策略（500字符/块，50字符重叠）
- ✅ **进度追踪**: 实时更新文档处理进度
- ✅ **OCR识别**: PDF文档支持GPT-4V视觉模型OCR
- ✅ **向量化**: 文档内容自动向量化存储到PGVector
- ✅ **故障恢复**: 完善的异常处理和重试机制

## 3. 数据库设计

### 3.1 file_detail 文件详情表

```sql
CREATE TABLE file_detail (
    id VARCHAR(64) PRIMARY KEY COMMENT '文件ID',
    user_id VARCHAR(64) NOT NULL COMMENT '用户ID',
    filename VARCHAR(255) NOT NULL COMMENT '文件名',
    file_type VARCHAR(50) NOT NULL COMMENT '文件类型（PDF/DOCX等）',
    file_size BIGINT COMMENT '文件大小（字节）',
    url TEXT NOT NULL COMMENT '存储URL',
    file_page_size INTEGER COMMENT '总页数/段落数',
    current_ocr_page_number INTEGER DEFAULT 0 COMMENT '当前OCR处理页数',
    ocr_process_progress DECIMAL(5,2) COMMENT 'OCR处理进度（%）',
    status VARCHAR(50) DEFAULT 'PENDING' COMMENT '处理状态',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_status (status),
    INDEX idx_file_type (file_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件详情表';
```

**状态流转**:
```
PENDING → PROCESSING → OCR_COMPLETED → VECTORIZING → COMPLETED
         ↓
      FAILED（任何阶段失败）
```

### 3.2 document_unit 文档单元表

```sql
CREATE TABLE document_unit (
    id VARCHAR(64) PRIMARY KEY COMMENT '文档单元ID',
    file_id VARCHAR(64) NOT NULL COMMENT '关联文件ID',
    content TEXT COMMENT '文本内容',
    page INTEGER COMMENT '页码/段落索引',
    is_ocr BOOLEAN DEFAULT false COMMENT '是否已OCR处理',
    is_vector BOOLEAN DEFAULT false COMMENT '是否已向量化',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_file_id (file_id),
    INDEX idx_is_vector (is_vector),
    INDEX idx_is_ocr (is_ocr),
    FOREIGN KEY (file_id) REFERENCES file_detail(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文档单元表';
```

### 3.3 embeddings 向量表（PGVector）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE embeddings (
    id VARCHAR(64) PRIMARY KEY,
    document_unit_id VARCHAR(64) NOT NULL,
    embedding vector(1536),  -- text-embedding-3-small维度
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_document_unit (document_unit_id)
);

-- 创建HNSW索引加速向量检索
CREATE INDEX embedding_hnsw_idx ON embeddings 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

### 5.2 PDF转图片处理

```java
/**
 * PDF页面转Base64图片
 * 使用PDFBox将PDF页面渲染为图片
 */
public class PdfToBase64Converter {
    
    public static String processPdfPageToBase64(
            byte[] pdfBytes, 
            int pageIndex, 
            String imageFormat) throws IOException {
        
        // 加载PDF文档
        PDDocument document = Loader.loadPDF(pdfBytes);
        
        // 创建PDF渲染器
        PDFRenderer pdfRenderer = new PDFRenderer(document);
        
        // 渲染指定页面为图片（300 DPI）
        BufferedImage image = pdfRenderer.renderImageWithDPI(
            pageIndex, 300, ImageType.RGB
        );
        
        // 转换为Base64
        ByteArrayOutputStream baos = new ByteArrayOutputStream();
        ImageIO.write(image, imageFormat, baos);
        byte[] imageBytes = baos.toByteArray();
        
        document.close();
        return Base64.getEncoder().encodeToString(imageBytes);
    }
}
```
